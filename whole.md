# Nanofield — Whole-Project State
*Last updated: September 9, 2026. Companion docs: `nanofield_ecommerce_plan.md` (business/catalog plan), `AGENTS.md` (commands + conventions).*

## Objective
Standalone brand store for an Indonesia-based semiconductor / electronic-component and appliance-spare-part retailer (ex-Shopee/TikTok "Toko Sanjaya"), relaunched as **Nanofield**. B2C first; B2B held in reserve via Medusa's dormant B2B modules.

## Layout
- `apps/backend` (`@nanofield/backend`) — Medusa v2 app. API at `http://localhost:9000`, admin at `/app`. Node 20+, PostgreSQL 15+.
- `apps/storefront` — Next.js storefront. `http://localhost:8000`, default region `id` (Indonesia/IDR — imported prices only exist in IDR, so `/dk/` shows blank prices).
- Package manager for this install is **npm** (`package-lock.json` at root). Never introduce a second lockfile. Install deps inside the app that needs them (`cd apps/backend` / `cd apps/storefront`).
- Turborepo at root: `npm run dev | build | start | lint | test`. Dev runs as the user's own `npm run dev` (`@nanofield/storefront:dev` + `@nanofield/backend:dev`, turbo); the manual `Start-Process` era is over.

Eleven glowing signal pulses travel the power, bus, motor-loop, comms, and relay nets (`hero-pulse` / `-2` / `-3` overlays, `pathLength=100` dash-flow; hidden under `prefers-reduced-motion`); via dots are vivid green (`#00e676` with matching glow) and keep their staggered blink. Draggable overlay symbols are a separate layer (`DraggableSymbol`, positions persist to localStorage). CSS classes `hero-tr` / `hero-via` / `hero-pulse*` / `hero-spin-slow` / `hero-via-blink` live in `styles/globals.css`. Known pre-existing lint note: `<a href="/store/">` in hero — leave it.
- **Catalog** (`modules/store`): sort, grid/list view toggle, category checkbox filter with "All products" reset. Fixed 80/page (10 rows × 8-col grid) — a per-page selector was built then removed Sep 9 by decision (speed/simplicity over choice). Hero pulses use dedicated `--hero-pulse` vars (vivid cyan light `#06b6d4`, aqua dark `#5eead4`) — one notch above traces and brand teal in both themes. Schematic layer stays `opacity-30` in light mode (tried 60/45/40 Sep 8 — all too strong; original subtlety wins) — dark stays 40. - **Search** (Sep 8, Phase 3 — storefront UI + one backend route, zero admin UI, no Meilisearch): `GET /store/search?q=` (backend `api/store/search`, Knex `.raw` via `__pg_connection__` — `manager` is NOT in route scope; Knex binds positionally so reused `$n` must expand to repeated `?`) ranks exact SKU/part_number/handle → title substring → trigram similarity → tsvector rank, typo-tolerant (verified `ne55`→NE555), returns ordered ids; storefront hydrates via `listProducts` id filter and re-sorts to rank (`searchProductIds`, `?q=` in `store/page.tsx`, `SearchField` on hero above ENTER CATALOG + full-width catalog header with count + clear (compact placeholder "Search part number"). Navbar `SiteSearch` icon (left of hamburger, 18px, `gap-x-6`): compact overlay (`max-w-lg`, no shortcuts block — stock Medusa has none) with live product suggestions (title/handle from extended `/store/search` items) + static pages (Home/Store/Cart/Checkout/Account/Orders/Addresses/Profile) + see-all-results. ## Backend — what is built
- **Admin branding** (`src/admin/lib/brand-dom.ts` + `widgets/branding.tsx` + `widgets/login-branding.tsx`): login circuit backdrop (22-trace board, 14 glyph types, 39+ spinning floaters, dash-flow signal pulses on all 21 via-terminated traces, vivid blinking vias), topbar badge, sidebar avatar blobs, favicon, Outfit+Manrope, static-copy scrubber (hides Docs/Changelog, rewrites Medusa strings; re-runs on click/focusin/popstate), settings-sidebar section spacing (inline-margin marking, same graceful-degradation tradeoff).
- **Admin routes**: `/app/overview` (Nanofield home, rank 1), `/app/ecomm-import` (E-comm Import, rank 2, `ArrowUpTray` icon; `@medusajs/icons@2.19.0` added), `/app/rajaongkir-services` (Shipping Services, `TruckFast` icon — service catalog UI, see shipping bullets).
- **Product datasheet widget** on `product.details.side` (toggle + URL + MPN). Datasheet UI rule (storefront `getDatasheetInfo`, shared by button + tabs): `no_datasheet` opt-out → direct `datasheet_url` (any product) → search fallback ONLY when `is_semiconductor` is explicitly true plus an identifier; title never used. The importer sets `part_number` + `is_semiconductor` from the SKU prefix (`classifySku`: IC/TRS/MOS/DIO/CAP/RES/IND/XTL/CRY/LED → true, everything else — incl. FUS appliance spares, MOD, tools — false).
- **Shopee importer** (Shopee-only; Tokopedia split off for later): thin CLI (`scripts/import-shopee.mjs`) calling Admin API routes (`src/api/admin/shopee-imports/`: `preview`, `execute`, `jobs`, `jobs/[id]`), shared engine (`engine.ts`), in-memory job store, multer middleware (`src/api/middlewares.ts`, 8MB). Preview + report UIs list skipped rows (pid/key + reason) and errors.
- **Admin bell** (Notification Center, `feed` channel via the local provider in `medusa-config.ts` + `notifyFeed` helper + `formatIDR` for `Rp 190.000` amounts). Consistent rule: important completions AND failures notify with title + one line; rows persist forever server-side (paginated drawer, unread = newer than your last open, refetch 60s — no expiry, no server delete; read rows auto-hide per browser with a "Show read" toggle, × hides any row). `feed-companion` topbar widget toasts arrivals newer than the last visit (60s poll, max 3, backlog never floods). Posters: Shopee import done/failed, bulk stock/delete done/failed (route-level too), `order.placed` + `order.canceled`, shipment pipeline (`order.fulfillment_created` packed, `shipment.created` shipped, AWB label added, `order.fulfillment_canceled`), `user.created/updated/deleted` (team security), `product-category.created/updated/deleted`. Deliberately silent: `product.*` (import volume — summaries cover it), `order.updated` (routine touches), returns/claims (ask if wanted). No delivered event exists (manual AWB — final leg confirmed by courier tracking).
- **Bulk stock & delete** lives on the Products list itself (`product-bulk-tools` widget, `product.list.before` zone): a compact two-button bar opens separate Set-stock / Delete drawers (Medusa UI `Drawer`), each with debounced search (50/page + Load more through all results), checkbox select ("All on screen" + "Select all N matching" up to 3000 across pages), preview, and execute; stock uses per-product quantities (global qty seeds each row at preview, rows stay editable); delete additionally confirms via `usePrompt`. The two buttons teleport next to the table's Create/Export button, else the Add-filter row (inline bar below the table as fallback); a persistent observer re-attaches after core re-renders, since Medusa exposes no toolbar zone. API errors surface with HTTP status + server message via toast and inline text. Backed by `src/api/admin/bulk-products/` (`preview` resolves SKUs to products/stock, `execute` set-stocks at the first stock location or permanently deletes — both 8-way parallel with a 5000-row cap, full counts never silently truncated); results also bell-notified. Drawer uses a single scroll container (no nested scroll traps); preview display capped at 200 rows.
- **Order analytics** on `/app/overview`: daily (30d) / monthly (12m) / yearly revenue + order-count charts (recharts — backend dep) with revenue/orders/avg stat cards, most-common currency formatting, and an empty state before the first sale.
- **RajaOngkir shipping** (Phase 1 code Sep 7, verified live Sep 8 — checkout verification still pending): custom fulfillment provider `src/modules/rajaongkir-fulfillment/` (`ModuleProvider(Modules.FULFILLMENT)`, `static identifier = "rajaongkir"`), injected into the fulfillment module's `options.providers` in `medusa-config.ts` (TOP-LEVEL `modules[]` entry crashes config load — `transformModules` requires `.service`; learned the hard way Sep 7) with `RAJAONGKIR_*` env (full set in `.env.template`). Targets the **V2 Komerce API** (`rajaongkir.komerce.id/api/v1`, `key:` header, SHIPPING COST key — not payment/QRIS). `calculatePrice`: origin subdistrict pinned `RAJAONGKIR_ORIGIN_ID=19363` (Pasar Jambi, Kota Jambi 36133) + destination via `domestic-destination` search (24h-cached), ONE `domestic-cost` call for all couriers split client-side by `code`, JNE REG exact + J&T cheapest (`jnt-eco` → EZ), summed variant weights. Live-verified Sep 8 (key works on V2 host; Jambi→Menteng 1kg = JNE REG 26000 + J&T EZ 22000). OKE/YES deliberately NOT offered: JNE publishes only REG (+JTR cargo) on Sumatera routes, so express labels would silently quote REG speed; NEVER throws — any failure returns flat `RAJAONGKIR_FALLBACK_AMOUNT` (Rp 20.000) so checkout can't block. `createFulfillment` stamps `{ courier, service, manual_booking: true }` (AWB booked manually). Importer engine parses Shopee `Berat` by header name (`detectWeightCol`, <100 → kg→g) into `weightGrams` on create/new/synced variants (500 g/item fallback when absent).
- `.gitignore` ignores `*.xlsx` at root. Never commit/print `.env` secrets. Never hand-edit migrations that may have run — add new ones.

## Gotchas
- Catalog cache: 5-min ISR on products/categories. Product AND category create/update/delete auto-purge the storefront via the `revalidate-storefront` subscriber → `POST /api/catalog/revalidate` (literal event strings — the `ProductEvents.*` constants have a prefix mismatch and don't fire for categories). Requires `STOREFRONT_URL` + matching `REVALIDATE_SECRET` in both env files (configured Sep 6). Restarting the storefront dev server flushes everything.
- Integration tests need a live PostgreSQL. No destructive DB commands without explicit confirmation.
- Backend must satisfy `@medusajs/eslint-plugin` recommended config — never disable a `@medusajs/*` rule; fix the code.
- `apps/storefront` lint currently ignore-patterns `src` files; `tsc --noEmit` has pre-existing project-wide React-type (TS2786) noise — when verifying, filter output to the files you touched.
- VSCode `@tailwind`/`@apply` "unknown at rule" warnings are editor-only noise, silenced via `.vscode/settings.json`. The Tailwind build is unaffected.
- Stock starter bug (fixed Sep 8, storefront `account-info/index.tsx`): the collapsible editor panel used `overflow-visible` while collapsed, leaving closed forms invisible-but-clickable over rows below — clicks on one section's Edit toggled/submitted a neighbor's form (phantom "updated successfully" badges on the wrong section). Fix: `overflow-hidden`. Badges are per-form state and now attribute correctly.
- Storefront account UX (Sep 8): billing editor surfaces the real server error (`errorMessage` from action state, was generic); address actions translate 401/`Unauthorized` into "Session expired — please log out and log back in, then retry" (`friendlyCustomerError` in `lib/data/customer.ts`); phone input fixed to `type="tel"`.
- Storefront `tsc` TS2786 noise on Button/Badge JSX is pre-existing on HEAD (verified via stash) — filter tsc output to touched files.
- Admin DOM tweaks must carry styling inline with the mark: an inject-once `<style>` tag goes stale for the session when its selector changes (Sep 8 spacing bug — marks applied, no visual change, survived even a versioned id). `applySettingsSpacing` sets `marginTop` directly and clears it on unmark.
- RajaOngkir integration targets the **V2 Komerce API, not legacy v1** (`api.rajaongkir.com/starter`): V2 free tier covers 17 couriers incl. **JNE + J&T** at 100 hits/day, has subdistrict-level ids, and the account/key live in the Collaborator dashboard.
